# Shell 提升生产力 · 方式全景

> 一句话回答：**不只四种**。alias / function / 环境变量 / shell 脚本是"核心装备层"，按"执行层（交互增强）"和"编排层（拿 shell 当胶水）"才是生产力长期增长的另两个维度。
> 本仓库里你已经用上了大部分，下面每类都标了对应文件。

---

## 第一层：定义层（先把命令和配置准备好）

这一层回答"怎么把每次都敲的长命令变成好调用"，是你最熟悉的骨架。

| 手段 | 干什么 | 何时用 | 本仓库对应 |
|---|---|---|---|
| **alias** | 给命令起短名、绑死默认参数 | 做"简写/固定开关"，纯替换不处理逻辑 | `Aliases/git.zsh` `Aliases/editor.zsh` |
| **function** | 可传参、可复用、能写逻辑的执行块 | 需要参数、多步、判断循环时 | `functions/productivity.zsh` `functions/model.zsh` |
| **环境变量 + PATH** | 给进程喂"配置/身份"，决定去哪找命令 | 存密钥、路径、服务地址 | `Aliases/env.zsh` `Aliases/path.zsh` |
| **封装 shell script** | 把整条流程固化成独立可执行文件 | 一次性拿不到 PWD、要独立进程/加班 | `api_keys/llm_api_call` |

> 区分：`source 脚本`＝在当前 shell 内跑（变量/函数/跳转留下，适合加载配置）；直接 `bash 脚本`＝子进程跑（跑完退出，不污染当前环境）。

---

## 第二层：执行层（让"打字"和"找文件"本身变快）

这一层**不新增命令**，却让每次操作变快，常常被归错地方：

| 方式 | 干什么 | 典型 |
|---|---|---|
| **Tab 补全** | 路径/命令/参数自动补齐 | 你 `cheatsheets/zsh_completion.md` 在用的就是它 |
| **语法高亮 + 自动建议** | 看错色就知错、边打边提示 | zsh-syntax-highlighting / zsh-autosuggestions 插件 |
| **模糊查找 fzf** | 按历史/文件/进程交互式点选 | `$(fzf)` 接在命令里选文件 |
| **管线组合** | 一行为完成现状：`find \| grep \| fzf` | 不需要 alias 也能爆发力 |
| **上下文跳转** | cd 历史、快速跳到常用目录 | zoxide / 别名 `cd项目名` |
| **按需加载 + hooks** | 进目录自动执行、分块 lazy 加载 | 你的 `loader.zsh`；`cd` 时自动 `source` 对应配置 |
| **现代 CLI 增强** | 更好的显示 | eza(better ls) / bat(better cat) / fd(better find) / ripgrep |

---

## 第三层：编排层（拿 shell 当"胶水 / 自动化工作台"）

这层是"两个量级"的提升——不只是打字快，而是让 shell 去替你做整套流程：

| 方式 | 干什么 | 本仓库对应 |
|---|---|---|
| **串多个工具/API** | 一条命令调外部服务（请求→解析→落盘） | `api_keys/llm_api_call` + `api_keys/domestic.zsh` |
| **调 LLM / AI** | 把 shell 变成 AI 助手入口 | `functions/model.zsh`（帮你选模型/跑推理） |
| **批处理 + 循环** | 用 shell 语言对一堆文件统一处理 | `functions/files.zsh` |
| **自己 env/密钥集中管理** | 密钥不进手敲命令、统一 source | `api_keys/` |
| **计划/定时** | 跟 cron/launchd 配合自动执行 | |

---

## 收口（为什么"只有四种"是错觉）

- **定义层（你列的四种）**是地基，解决"重复敲"；
- **执行层**解决"打得慢、找得累"——甚至不用新增任何配置；
- **编排层**解决"手动做整套事"——这是生产力质变的地方，你的 `api_keys` + `functions/model.zsh` 已经在这层。

**一句话：真正持续提高效率 = 定义层打底 + 执行层提速 + 编排层自动化，三件套缺一也远不够。**
